# WebPost

한 사람만 쓰는 마이크로 블로그. Telegra.ph 의 마음(제목 한 줄, 본문 한 칸, 끝)에
WebPaper 의 옷(같은 카드, 같은 시트, 같은 한국어 검색)을 입혔다.
포인트 색은 `#B22222` 하나뿐이다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면의 뼈대. 상단바·피드·시트·글쓰기·설정 |
| `app.css` | 디자인 토큰과 전부. WebPaper `app.css` 를 이어받았다 |
| `app.js` | 저장소·검색·본문 렌더·피드·글쓰기 |
| `posts.json` | 글 목록. 사이트가 읽는 유일한 데이터 |

## 두 가지 모드

- **배포본**(http/https) — 모두가 `posts.json` 을 읽는다. 쓰기·수정·삭제 버튼은
  이 브라우저에 GitHub 토큰이 있을 때만 보인다. 남에게는 그냥 읽는 블로그다.
- **미리보기**(파일로 열었을 때) — 이 브라우저의 `localStorage` 에만 쓴다.
  배포본과 데이터가 섞이지 않는다.

## 배포

1. 빈 저장소를 하나 만든다(예: `webpost`).
2. 이 폴더의 파일 네 개를 그 저장소 루트에 올린다.
3. Settings → Pages → Branch `main` / `/ (root)` → 저장.
4. 폰에서 그 주소를 연다 → **설정 → 저장소(GitHub)** 에 아이디·저장소·토큰을 넣고
   **연결 확인** → **저장**. 토큰은 fine-grained 로 `webpost` 저장소 하나에
   `Contents: Read and write` 만 주면 된다(클래식이면 `repo`). 이 브라우저에만 저장된다.

글을 쓸 때는 **화면이 들고 있는 목록을 파일에 덮어쓰지 않는다.** 매번 파일을 새로
읽어(GitHub API) 한 가지 동작만 얹고 커밋한다. 그래야 사이트 캐시가 옛 목록을 준
순간에도 방금 지운 글이 되살아나지 않는다. 글쓴이는 CDN 대신 API 에서 읽으므로
자기 화면에는 즉시 반영되고, 남의 화면에는 30초~1분 뒤에 나타난다.

이후로는 사이트에서 **쓰기** → 저장. GitHub 에 커밋이 하나 생기고 Pages 가 다시 그린다
(보통 30초~1분). 글 하나에 커밋 하나라, GitHub 의 기록이 그대로 글의 역사가 된다.

## 글 한 편의 모양

```json
{ "id": "p1a2b3", "d": "2026-11-24", "t": "제목", "b": "본문", "c": 1795482000000, "u": 0 }
```

- `d` — 화면에 보이는 날짜. 연·월·일까지만. 글마다 직접 정한다.
- `t` — 제목. 비워도 된다(그러면 본문이 굵게 올라간다).
- `c` — 만든 시각. 같은 날 여러 글의 순서를 정하는 데만 쓰고 화면에는 안 나온다.
- `u` — 고친 시각.

## 본문 서식

`**굵게**` · `*기울임*` · `` `코드` `` · `> 인용` · `- 목록` · 이미지 주소만 붙여넣기.
빈 줄로 문단을 나눈다. 그 이상은 없다.

## 검색

WebPaper `search.html` 의 규칙 그대로. 조사를 떼고(`서식은` → `서식`),
초성으로 찾고(`ㄱㅅ` → 검색), 여러 단어는 모두 들어가야 하고, 날짜로도 찾는다(`11월`).
